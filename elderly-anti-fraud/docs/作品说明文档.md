# 「银发守护宝」老年人防诈骗守护小程序 · 作品说明文档

> 版本：v2.1 ｜ 更新日期：2026 年 9 月 ｜ 技术栈：微信小程序原生 + 微信云开发（Serverless）

---

## 一、作品概述

「银发守护宝」是一款面向老年群体及其家庭成员的反诈骗守护类微信小程序。产品以"识别—求助—举报—守护"为核心链路，在传统规则匹配识别的基础上，深度融合腾讯混元大模型（hy3）的生成式 AI 能力，为老年人提供**低门槛、强兜底、可协同**的全流程反诈防护服务。

- **产品定位**：老年人身边的"AI 反诈顾问 + 家庭守护网络"
- **核心特色**：AI 智能识别、多轮对话咨询、每周 AI 防护画像、子女远程协同预警、紧急救援模式
- **运行平台**：微信小程序（免安装、低学习成本，契合老年用户使用习惯）

---

## 二、开发背景与社会意义

据公安部公布的数据，电信网络诈骗已成为发案最多、上升最快、涉及面最广的犯罪类型，而老年群体因信息获取滞后、数字技能薄弱，是"保健品骗局""冒充公检法""中奖诈骗"等高发骗术的主要受害人群。传统反诈宣传以单向科普为主，缺乏**即时性**（遇到可疑信息时无人可问）与**针对性**（不了解老人个体的受骗风险特征）。

本作品针对上述痛点，提出三点解决思路：

1. **即时可问**：将 AI 大模型封装为"7×24 小时反诈顾问"，老人遇到可疑短信、链接、电话时，随手粘贴即可获得风险研判；
2. **因人施防**：基于用户识别历史，AI 每周自动生成个性化"防护画像"，指出薄弱环节并给出针对性建议，变"大水漫灌"为"精准滴灌"；
3. **家庭协同**：识别出高风险内容时自动向家庭成员（绑定微信）推送预警，弥补老人独自判断能力的不足。

## 三、目标用户与需求分析

| 用户角色 | 核心诉求 | 对应功能 |
|---|---|---|
| 老年用户（主用户） | 看不懂可疑信息，需要有人"帮我看看" | 智能识别、AI 顾问对话、快捷提问 |
| 老年用户 | 已经受骗，不知如何止损 | AI 紧急救援模式（止付、冻结、取证、报警指引） |
| 家庭成员（协同用户） | 远程了解父母遭遇的风险 | 家庭守护页、风险预警列表、AI 摘要 |
| 全体用户 | 学习防骗知识、参与反诈互助 | 案例库、知识库、社区互助、举报通道 |

适老化设计贯穿全站：**大字号、高对比度、图标化导航、一键式操作、语音友好文案**，避免老年用户因操作复杂而弃用。

## 五、技术架构

### 5.1 总体架构

采用**微信云开发（TCB）Serverless 架构**，前端为小程序原生框架，后端全部由云函数承载，数据层为云开发文档型数据库，无需自建服务器。

```
┌─────────────────────────────────────────────┐
│  小程序前端（11 个页面，原生 WXML/WXSS/JS） │
└──────────────────┬──────────────────────────┘
                   │ wx.cloud.callFunction
┌──────────────────▼──────────────────────────┐
│            云函数层（11 个函数）             │
│  ┌─────────────┬─────────────┬───────────┐  │
│  │  AI 能力层   │  业务服务层   │  系统运维层│  │
│  │  aiChat     │  dataService │  initDB   │  │
│  │  aiProfile  │  identifyFraud│ cleanupTimer│
│  │  aiSummary  │  getKeywords │  login    │  │
│  │  identifyFraudAI          │           │  │
│  │  identifyImageAI          │           │  │
│  └─────────────┴─────────────┴───────────┘  │
└──────┬───────────────┬──────────────────────┘
       │ cloud.ai()     │ db（管理员权限）
┌──────▼──────┐  ┌──────▼───────────────────┐
│ 混元大模型   │  │  云数据库（8 个集合）      │
│  (hy3)      │  │  users / identifyHistory  │
│             │  │  fraudCases / keywords    │
│             │  │  familyAlerts / aiProfiles│
│             │  │  reports / communityPosts │
└─────────────┘  └──────────────────────────┘
```

### 5.2 关键技术实现

**（1）AI 能力集成（5 个 AI 云函数）**

通过 `wx-server-sdk 4.x` 的 `cloud.ai()` 接口接入腾讯混元大模型（`hy3`），采用统一的调用范式：

```js
const ai = cloud.ai();
const model = ai.createModel('cloudbase');
const res = await model.generateText({
  data: {
    model: 'hy3',
    messages: [{ role: 'system', content: SYSTEM_PROMPT }, ...],
    temperature: 0.3
  },
  timeout: 30000
});
```

五个 AI 云函数各司其职：

| 云函数 | 职责 | 工程要点 |
|---|---|---|
| identifyFraudAI | 诈骗内容智能研判 | 提示词约束输出结构化 JSON（风险等级 / 8 类诈骗类型 / 解释 / 建议），保证前端可解析 |
| aiChat | 反诈顾问多轮对话 | system prompt 注入"反诈专家"角色设定；携带历史上下文实现多轮追问；支持 rescue 紧急救援模式切换专属提示词 |
| aiProfile | 每周防护画像 | 聚合用户近 7 天识别历史后交由 AI 生成；**按"用户 + 自然周"结果缓存**，周内不重复消耗 AI 调用 |
| aiSummary | 家庭预警摘要 | 将多条预警记录压缩为 ≤30 字的老人友好表述 |
| identifyImageAI | 图片识诈 | 接收图片临时链接，OCR 提取文字后交由 AI 判定风险 |

**（2）身份体系与数据安全**

- 通过 `wx.login` 获取 `code`，由 `login` 云函数经 `cloud.getWXContext()` 解析 **OPENID** 作为全局唯一用户标识，upsert 至 `users` 集合；
- `dataService` 云函数在入口处**强制以服务端 OPENID 覆盖客户端传入的 userId**，从源头杜绝客户端伪造身份读取他人数据的横向越权风险；
- 全部数据读写经云函数以管理员权限代理执行，客户端不持有数据库直连权限，天然隔离攻击面。

**（3）规则与 AI 双引擎识别**

`identifyFraud`（规则引擎）与 `identifyFraudAI`（大模型）并存：AI 为主判定路径，关键词规则匹配作为兜底。两套引擎的判定结果统一落库至 `identifyHistory`，既支撑画像统计，也保证 AI 服务不可用时核心功能零感知降级。

**（4）家庭协同预警**

`identifyFraud` 在判定为高风险时自动调用 `dataService.addFamilyAlert` 写入 `familyAlerts` 集合，家庭成员打开小程序即可在守护页看到分级预警（红/橙/黄风险色条），并由 `aiSummary` 生成一句话摘要，降低子女侧的阅读成本。

### 5.3 可靠性与降级设计（容错兜底）

针对云端 AI 服务可能出现的限流（429）、超时、异常返回，所有 AI 调用均设计了**三层降级链路**，确保任何情况下主流程不中断：

```
Level 1  AI 大模型调用成功 → 返回生成结果
Level 2  AI 调用失败 → 降级至关键词规则引擎（identifyFraud 同款规则）
Level 3  规则也无命中 → 返回预设的通用安全提示 + 建议咨询人工
```

该设计经实际验证：在 AI 配额未开通期间，小程序全部功能可正常演示，无白屏、无报错、无流程中断。

## 六、创新点总结

1. **"AI 画像 + 因人施防"**：不同于静态科普类产品，本作品持续积累用户识别行为数据，以周为周期由 AI 生成动态防护画像，形成"使用越多—画像越准—防护越针对性"的正向飞轮；
2. **AI 紧急救援模式**：针对"已受骗"这一传统反诈产品普遍忽视的场景，提供止付、冻结、取证、报警四步引导，把服务边界从"事前预防"延伸至"事后止损"；
3. **双引擎 + 全链路兜底**：大模型与规则引擎互为冗余，工程上保证了对第三方服务依赖的可控性，演示与生产均不"翻车"；
4. **身份安全的服务端加固**：OPENID 服务端覆盖机制，在零自建服务器的 Serverless 架构下仍实现了严格的租户数据隔离。
